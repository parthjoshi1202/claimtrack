# ClaimTrack: project brief for Claude

## What this is
A portfolio DevOps project by Parth Joshi. A small FastAPI insurance-claims API
(`/health`, `POST /claims`, `GET /claims/{id}`, `PATCH /claims/{id}/status`;
statuses `submitted -> in_review -> approved | rejected`) deployed to AWS with Terraform
and GitHub Actions. The app is deliberately simple; the infrastructure, pipeline and
operations are the point.

## Architecture (dev)
- Region: us-east-2. VPC across 2 AZs: 2 public subnets (ALB + ECS tasks), 2 private subnets (RDS).
- No NAT gateway. Tasks get public IPs only to pull images; their security group allows inbound only from the ALB.
- ECS Fargate, ARM64, 0.25 vCPU / 0.5 GB. ECR with scan on push and a keep-3-images lifecycle rule.
- Aurora Serverless v2 PostgreSQL 16.x (aws_rds_cluster + one db.serverless aws_rds_cluster_instance),
  min 0 / max 2 ACUs, seconds_until_auto_pause = 300, encrypted, private. Password generated by Terraform,
  stored in SSM Parameter Store (SecureString), injected into the task as a secret.
- So the database can actually pause: /health must NOT query the database; the app's connection pool
  must close idle connections (e.g. short pool_recycle or no persistent pool); DB connect timeout > 15 s with retries.
- CloudWatch logs (1-day retention), dashboard, alarms -> SNS email. ECS deployment circuit breaker with rollback.
- Terraform: modules `network`, `database`, `service`; env `infra/envs/dev`; S3 backend with `use_lockfile = true`.
  Provider `default_tags`: Project = claimtrack, Owner = parth.
- GitHub Actions with OIDC (no stored AWS keys): `ci.yml` (pytest, fmt, validate, plan, Checkov, Trivy, Infracost),
  `deploy.yml` (main or manual), `nightly-destroy.yml` (scheduled `terraform destroy`).

## Rules
- Cost: keep the total project under $10. Never add NAT gateways, EKS, multi-AZ RDS or Secrets Manager
  without asking. Prefer the cheapest option and say what it costs per hour.
- Write one file or module at a time. After writing, explain every block in plain words and why
  it was chosen over the alternatives.
- Never invent experience or metrics for the README; leave [placeholders] for numbers Parth measures himself.
- Security basics always: least-privilege IAM, no secrets in code or state outputs, non-root containers.
- End each step with 2 interview questions a bank's DevOps hiring manager could ask about it.
